# 샷 연속성 (Shot Continuity) — 뉴스형 그룹핑 · 생성 모드 선택 · 연결부 검사

생성 실행 전 반드시 읽는다. "사진을 이어붙인 영상"(슬라이드쇼)을 막는 규칙이 전부 여기 있다.

## 왜 샷 단위인가

씬(2-5초)마다 독립된 스틸→클립을 만들면 씬 사이에 공유되는 것(공간·조명·인물·움직임)이 없어 슬라이드쇼가 된다. 연속성은 편집으로 못 만든다 — **생성 단계에서** 확보한다:

1. `hook`·`context`·`evidence`·`cta`·인물 씬 2-3개를 **샷 하나(8-15초)로 묶어 한 번에 연속 생성**
2. 샷 사이는 **이어가기(video_extension)** 또는 **전환 생성(start/end frame)**으로 잇는다
3. 전 샷에 **공통 스타일 프리픽스**(no-text 지시 포함)를 고정해 톤 편차를 없앤다

**뉴스형 예외 — 의도된 스틸 경로 (샷으로 묶지 않는다)**:
- `data_card`·`caution`: 자막이 주인공. 배경이 움직이면 글자가 안 읽힌다 — 정지 배경 + 조립 켄번스가 정답
- `demo`(guide): 자세 정확도 우선 — 2스틸 교차컷 유지

조립 계약과의 관계: 샷은 생성 단위일 뿐, 조립 지시서에는 **씬 단위로 분할해 싣는다** (같은 url + 씬별 trim_to). 씬 시간표·출처 크레딧 타이밍은 그대로 유효하다.

## 샷 그룹핑 규칙 (스토리보드에 샷 플랜이 없을 때 여기서 수행)

- **묶는다**: 같은 공간에서 이어지는 씬들, 하나의 동작·상황 흐름, 같은 person_group이 연속 등장하는 씬들
- **분리한다**: 공간·시간대 전환, 톤 급전환(통념→반박), `data_card`·`caution`·`demo` 씬(스틸 경로), 스틸 경로 씬을 사이에 둔 앞뒤 구간
- **훅은 단독 샷** — 가장 중요한 3초이므로 독립 생성·독립 재시도가 가능해야 한다
- 샷 길이 = 묶인 씬들의 배정 초 합계, 8-15초 기준 (모델 duration 상한 안에서). 배정 초보다 짧은 샷을 만들지 않는다
- 그룹핑 결과는 표(샷 ID·씬 범위·연결 방식)로 제시하고 사용자 확인 후 생성에 들어간다
- 샷 사이에 스틸 경로 씬이 끼면 그 경계의 연결 방식은 자동으로 `cut`이다 (extension 불가)

## 생성 모드 선택 트리 (샷마다 — 스토리보드 전환 가이드의 연결 방식 지정을 따른다)

```
[앵커 샷 = 첫 샷]
   → 참조 생성: 프롬프트 = 공통 스타일 프리픽스 + 샷 비트 서술
     인물 포함이면 앵커 스틸을 start_image로 (SKILL.md 인물 일관성 규칙 a)

[후속 샷 N]
   ├─ extension (같은 공간·연속 동작)
   │    → video_extension (forward): 직전 샷의 job_id를 참조로 넘겨 이어가기.
   │      인물은 실제 픽셀이 연장되므로 identity가 유지된다 (연속 테이크 문구는 여전히 필수)
   ├─ cut (공간/상황 전환, 스틸 경로 씬 전후)
   │    → 새 참조 생성 (동일 스타일 프리픽스 + 동일 person 앵커)
   └─ transition (전환 자체가 연출 — 매치컷 등)
        → start_image(직전 샷 끝 프레임 캡처) + end_image(다음 샷 첫 프레임)로
          전환 구간을 별도 짧은 샷(2-4초)으로 생성
```

- 모드 이름(video_extension 등)은 `models_explore`로 조회한 **실제 모델의 파라미터·롤 이름으로 치환**해 호출한다. 미지원 모델이면 SKILL.md 모델 폴백 규칙(끝 프레임 캡처 → start_image 대체)
- extension 체인이 길어지면(3연장 이상) 화질 드리프트가 누적된다 — 4샷 이상이면 중간에 참조 생성 샷을 한 번 끼워 리셋한다

## 호출 규약 (Higgsfield MCP)

```
1) (인물 있으면) 앵커 스틸 생성 → 승인 게이트 → media_id 확보
2) 비용:  generate_video(params:{…, get_cost:true}) — 드래프트·본 생성 각각
          프리플라이트, 합산 고지 (비용 게이트 G1)
3) 드래프트: 본 생성과 동일한 prompt·medias로 앵커 샷 1개를 최저 해상도(480p)·
          fast/mini 변형으로 생성 → 사용자 승인 (비용 게이트 G2).
          승인 전에는 1080p 호출 금지
4) 생성:  generate_video(params:{
            model: "<카탈로그 실제 id>",
            prompt: "<공통 스타일 프리픽스 + 샷 비트 (+ 인물이면 연속 테이크 문구)>",
            aspect_ratio: "9:16",          ← 반드시 명시 (기본이 16:9인 모델 있음)
            duration: <샷이 덮는 씬 배정 초 합계 이상>,
            generate_audio: false,          ← 오디오는 assemble의 믹스 담당
            medias: [
              {value: "<앵커 스틸 media_id>", role: "start_image"}, ← 인물 샷만
              {value: "<직전 job_id>", role: "<extension 롤>"}     ← 이어가기 샷만
            ]})
5) 대기:  job_status / jobs_wait → 완료 후 URL 수집 (만료 전 즉시 다운로드 권장)
```

- 여러 독립 샷(cut 연결)은 batch 도구로 병렬 생성 가능하되, **extension 체인은 순차** (직전 job_id가 필요하므로)

## 공통 스타일 프리픽스

앵커 샷 확정 시 한 줄로 뽑아 전 샷 프롬프트 맨 앞에 동일하게 붙인다. **뉴스형은 no-text 지시가 프리픽스에 반드시 포함된다**:

```
예) "muted documentary editorial look, soft natural light, desaturated tones,
    vertical 9:16, no text, no logos, no on-screen numbers, no signage"
```

- 조명·색감·질감·촬영 룩 + no-text 지시. 씬 내용은 넣지 않는다
- 스토리보드가 샷 플랜에 프리픽스를 확정해뒀으면 그 값을 그대로 쓴다

## 연결부(seam) 검사 — Step 4

샷 경계마다 직전 샷 **끝 프레임** vs 다음 샷 **첫 프레임**을 나란히 놓고 판정:

| 항목 | 합격 기준 |
|---|---|
| 공간·배경 | extension 연결이면 동일 공간으로 자연스럽게 이어짐. cut 연결이면 점프가 어색하지 않음 |
| 조명·색조 | 톤 점프 없음 (프리픽스 고정이 지켜졌는지) |
| 인물 | 같은 person_group이면 동일 인물·의상·머리 (identity switching 불합격) |
| 글자·로고 | 경계 프레임에도 생성된 글자·숫자·로고 없음 (뉴스형 제1원칙) |

- 판정을 조립 지시서 `shots[].seam_check`에 기록한다 (pass / fail / manual)
- 불합격 시: 해당 연결만 재생성 — extension이면 동작 서술을 더 구체화해 1회 재시도, 그래도 실패면 그 경계는 cut 연결로 설계 변경하고 사용자에게 고지

## 조립 지시서와의 연결

- 샷 클립을 씬 단위로 분할해 `clips[]`에 싣는다: 같은 샷의 씬들은 **같은 url**, 씬별 `trim_to` (샷 내 누적 시각 기준), `shot` 필드에 샷 ID (스틸 경로 클립은 `null`)
- `trim_to` 구간 합 = 샷이 덮는 씬들의 배정 초 합 ≤ 샷 duration
- 같은 shot의 인접 씬 경계는 이음새가 없으므로 **`assembly.transitions`에 지정하지 않는다** — 자막·나레이션·크레딧 싱크의 기준점일 뿐이다. 전환(xfade)은 샷과 샷 사이, 샷과 스틸 경로 씬 사이에만 지정한다
