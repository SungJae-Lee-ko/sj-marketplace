# 쇼핑쇼츠 영상 생성 (Video Generation Orchestrator)

**책임 한 줄**: 확정된 스토리보드(샷 플랜) + 레퍼런스(A·B) 입력 → 레퍼런스 반입 → 샷 단위 연속 생성 체인 실행 → 원본 대조·연결부 검수된 샷 클립 세트 + 조립 지시서 반환.

## 두 개의 1급 실패 — 이 스킬이 존재하는 이유

1. **제품 왜곡**: 라벨 글자·로고·색·비율·부품 형태가 원본과 달라지는 것. 생성 모델은 제품을 재해석해 다시 그리므로, 제품 픽셀이 **생성을 통과하는 횟수를 최소화**하는 것만이 근본 대책이다. 따라서 제품 실사진(A)은 이미지 모델로 스틸을 재생성하지 않고(구 파이프라인 금지), 영상 모델의 참조 입력으로 **직접** 전달한다. 상세: **references/product-fidelity.md** (제품 등장 샷이 하나라도 있으면 작업 전 읽는다)
2. **슬라이드쇼**: 씬마다 독립된 스틸에 카메라 무빙만 입혀 이어붙이면 "사진을 붙인 영상"이 된다. 연속성은 편집이 아니라 **생성 단계에서** 확보한다 — 씬 2-3개를 샷 하나로 묶어 연속 생성하고, 샷 사이는 이어가기/전환 생성으로 잇는다. 상세: **references/shot-continuity.md** (생성 실행 전 반드시 읽는다)

## 엔진 구성 (기본값 — 사용자 지정 시 그 값 우선)

| 역할 | 기본 | 비고 |
|---|---|---|
| 샷 생성 (t2v·참조 생성·이어가기·전환) | **Higgsfield / Seedance 계열 최상위** | `models_explore`로 현재 카탈로그를 조회해 실제 모델 id로 호출. 선택 기준: `image_references`(제품 identity)·`video_references`·`video_extension`·`start_image`+`end_image`를 지원하는 최상위 버전 |
| 배경 제거 (무생성 컴포지팅용) | Higgsfield `remove_background` | 보존 강등 단계에서만 사용 |
| 배경/인포그래픽 **스틸** (선택) | GPT-Image-2 (codex 브리지) 또는 Higgsfield 이미지 | **제품 미등장** 삽화 컷 전용. 제품 씬 스틸 재생성에는 어떤 이미지 모델도 쓰지 않는다 |

- 모델 카탈로그에 요구 기능이 없으면: 기능별 차선 모델(예: start/end frame 지원 타 모델)을 조회해 제안하고 사용자 확인 후 진행

## 사전 조건 (모두 충족해야 시작)

1. shorts-storyboard 산출물이 확정됨 — **샷 컬럼(샷 그룹핑) + 씬별 제품 등장 여부** 포함. 샷 컬럼이 없는 구버전 스토리보드면 shot-continuity.md의 그룹핑 규칙으로 샷 플랜을 먼저 만들어 사용자 확인을 받는다
2. 영상 생성 MCP(Higgsfield) 연결 확인 — 없으면 샷별 프롬프트 + 참조 매핑만 정리해 주고 종료
3. **A자료(제품 실사진) 확보** — 제품 등장 샷이 있는데 A가 없으면 생성하지 않고 A를 요청한다 (프롬프트만으로 제품을 그리면 상상 제품이 나온다)
4. **비용 게이트 사다리**(아래 섹션) 통과 — G2 드래프트 승인 전에는 본 생성 해상도(1080p) 호출 금지

## 생성 파이프라인

```
[Step 0] 레퍼런스 반입
   └─ A(제품 실사진): media_upload → 업로드 → media_confirm → media_id 확보.
      다각도(정면·측면·상단)가 있으면 전부 반입 — 각도가 많을수록 왜곡이 줄어든다
   └─ B(참고영상): 모션·무드 전달용으로 반입 (video_references).
      단, 타사 제품·로고가 크게 나오는 B는 참조로 쓰지 않는다 (오염 위험 고지)
   └─ 인물/캐릭터 일관성 자산 (시리즈물만, 아래 섹션)
   ↓
[Step 1] 샷 플랜 확정
   └─ 스토리보드의 샷 그룹핑 검토: 샷당 씬 2-3개, 8-15초.
      훅은 단독 샷. 규칙·예외는 shot-continuity.md
   ↓
[Step 2] 샷 생성 (드래프트 게이트 통과 후, 앵커 → 체인 순서)
   └─ 앵커 샷(첫 샷): 참조 생성 — A 전체를 image_references로,
      B를 video_references로, 프롬프트는 카메라·조명·배경·동작 비트만
      (제품 형태를 텍스트로 재묘사하지 않는다)
   └─ 후속 샷 — 모드 선택 (shot-continuity.md의 트리):
      · 같은 공간에서 이어지는 동작 → video_extension (직전 샷 job_id 이어가기)
      · 공간/상황 전환 → 새 참조 생성 + 동일 A 참조 세트 + 공통 스타일 프리픽스
      · 의도된 전환 연출(매치컷 등) → start_image + end_image로 전환 자체를 생성
   └─ 공통: aspect_ratio "9:16" 명시, 씬 묶음 길이에 맞는 duration 지정.
      오디오는 기본 generate_audio:false (BGM·자막은 편집 단계) — 현장음이
      필요한 샷만 사용자 확인 후 true
   ↓
[Step 3] 검수 — 3종 대조
   └─ 원본 대조 (제품 등장 샷): A 원본 vs 샷의 제품 노출 프레임
      (라벨 텍스트·로고·색·비율·부품 형태) — product-fidelity.md 체크리스트
   └─ 연결부 검사: 샷 경계에서 직전 샷 끝 프레임 vs 다음 샷 첫 프레임
      (공간·조명·제품 상태 연속성) — shot-continuity.md
   └─ 샷 간 일관성: 앵커 샷 vs 마지막 샷의 제품 렌더링 비교 (드리프트 누적)
   └─ 불합격 시: 프롬프트 수정 반복이 아니라 **보존 대응 사다리로 강등**
      (참조 강화 → 정지 앵커 → 무생성 컷 → 실촬영) — product-fidelity.md
   ↓
[Step 4] 조립 지시서 산출 (아래 형식)
```

## 샷 카메라 연출 가이드 (프롬프트에 넣는 무빙 지시)

| 샷 성격 | 카메라 지시 | 이유 |
|---|---|---|
| 훅 (0-3초) | fast push-in / reveal | 첫 프레임 시선 고정. 제품 훅이면 줌 강도 중간 이하 |
| 제품 클로즈업 비트 | slow push-in / hold | **orbit(회전)·플립 금지** — A에 없는 면을 상상 생성해 왜곡된다. A에 해당 각도 사진이 있을 때만 그 각도 간 전환 허용 |
| 상황/사용 비트 | pan / handheld follow | 생활감. 샷 내 연속 동작으로 생동감 확보 (스틸+줌으로 흉내내지 않는다) |
| 비교/증거 비트 | hold + 화면 분할 여지 | 정보 전달은 무빙 최소화 |
| CTA | hold / slow pull-back | 자막·행동 지시가 주인공 |

- 사용자가 다른 연출을 지정하면 우선하되, 제품 샷에 orbit류를 지정하면 왜곡 위험을 고지하고 확인받는다

## 인물·캐릭터 일관성 (시리즈물/모델 등장 시)

```
[Q1] 같은 인물·마스코트가 여러 샷 또는 여러 회차에 반복 등장하나?
   ├─ 아니오 → skip (제품 단독 모드)
   └─ 예 → 인물 기준 이미지를 A와 같은 방식으로 반입해 전 샷의
          image_references에 고정. 등록된 캐릭터(character_id)가 있으면 그 id 사용
```

- 실존 인물 얼굴은 본인 동의를 확인한다. 타인·유명인 얼굴은 거절

## 비용 게이트 사다리 (승인 없이 생성 호출 금지)

영상 생성은 크레딧이 비싸다. 확신이 낮은 단계에서 비싼 호출을 하지 않도록, 게이트를 위에서부터 순서대로 통과한다:

| 게이트 | 비용 | 확인하는 것 |
|---|---|---|
| G0. 샷 플랜·프롬프트 승인 | 0 | 연출 방향, 씬 묶음, 샷별 프롬프트 문안 |
| G1. `get_cost:true` 실측 프리플라이트 | 0 | 드래프트·본 생성 각각의 실제 크레딧 (생성 없이 조회) — 합계 + 재생성 예비 +20% 고지 |
| G2. **드래프트 생성** — 앵커 샷 1개 | 저가 | 제품 재현·스타일·모션이 원하는 방향인지. 본 생성과 **동일한 프롬프트·참조**로, 해상도만 최저(480p)·fast/mini 변형 사용 |
| G3. 본 생성 (1080p, 전 샷 체인) | 고가 | G2에서 확정된 프롬프트·참조 그대로 실행 |

- **스틸 프리뷰를 게이트로 쓰지 않는 이유**: 스틸을 승인해도 영상 모델이 프레임을 다시 그리므로 최종 결과를 예고하지 못하고(승인한 사진과 다른 영상이 나옴), 제품 씬에서는 스틸 재생성 자체가 왜곡원이다. 저해상도 **드래프트 영상**이 구도·모션·제품 재현을 모두 미리 보여주는 진짜 프리뷰다
- 드래프트 불합격이면 프롬프트·참조를 수정해 **드래프트만** 재시도 — 본 생성 크레딧은 방향이 확정된 뒤에만 쓴다
- 무료 무제한 생성(unlim)을 지원하는 모델·잔여분이 있으면 드래프트에 우선 사용을 제안한다 (`models_explore`의 supports_unlim → `use_unlim`)
- 샷이 많으면(5개 이상) 드래프트는 앵커 + 성격이 다른 대표 샷 1개까지로 제한한다

## 출력 형식 (조립 지시서)

```json
{
  "storyboard_ref": "제품명-v1",
  "engine": "higgsfield/<실제 모델 id>",
  "references": {"product": ["media_id…"], "motion": ["media_id…"], "identity": []},
  "shots": [
    {"shot": 1, "scenes": [1, 2], "role": "hook+product", "product_shot": true,
     "mode": "omni_reference", "duration": 10, "job_id": "…", "url": "…",
     "cut_points": [{"scene": 2, "at": 3.0}],
     "review": {"fidelity": "pass", "seam": null, "note": "라벨·로고·색상 원본 일치"}}
  ],
  "assembly": {
    "sequence": [1, 2, 3],
    "seams": [{"between": [1, 2], "type": "extension", "check": "pass"}],
    "subtitles": "스토리보드 자막 컬럼 참조 (cut_points 기준 타이밍)",
    "bgm_cue": "스토리보드 오디오 컬럼 참조",
    "export": "9:16 1080×1920, 샷 순서대로 붙이고 cut_points에 자막 싱크"
  },
  "ai_disclosure": "유튜브 업로드 시 '변경·합성된 콘텐츠' 공개 설정 필요"
}
```

- `cut_points`: 샷 안에서 씬(자막·비트)이 바뀌는 시점 — 편집 앱에서 자막 싱크 기준
- 조립은 사용자가 편집 앱(CapCut 등)에서 수행 — 샷이 이미 이어져 있으므로 트랜지션 효과 없이 순서대로 붙이는 것이 기본

## 이 스킬을 사용하지 말아야 할 때

- **스크립트·콘티가 아직 없음** → shorts-script / shorts-storyboard 먼저
- **단일 이미지·단일 클립만 필요** → 영상 생성 MCP 직접 호출이 빠름
- **실촬영으로 확정된 프로젝트** → 본 스킬 불필요, 스토리보드의 촬영 체크리스트 사용
- **상세페이지용 이미지 세트** → 본 플러그인 범위 밖 (moai commerce-detail-page-image 계열)

## 다음 단계 (체이닝)
