# 쇼핑쇼츠 영상 생성 (Video Generation Orchestrator)

**책임 한 줄**: 확정된 스토리보드 + (sales) 레퍼런스 A자료 / (habit) 캐스팅 시트 입력 → 씬별 [이미지 생성 → image-to-video] 체인 실행 → 검수된 씬 클립 세트 + 조립 지시서 반환.

## 사전 조건 (모두 충족해야 시작)

1. shorts-storyboard 산출물이 확정됨 (없으면 그 스킬로 먼저). **씬 표의 8개 고정 컬럼(#·시간·화면 구성·앵글/무빙·나레이션·자막·오디오·person_group)과 씬 시간표가 모두 있어야 한다**
   - `person_group` 반려 조건은 **인물이 등장하는 씬이 있는데 그 씬의 ID가 비어 있을 때**다. 인물이 아예 없는 기획(전 씬 `—`)은 정상이며 제품 단독 모드로 진행한다
2. **`content_type` 확인** (`sales` | `habit`) — 스토리보드 표 아래에 있다. **아래 사전 조건 5(5-A/5-B)와 생성 경로가 이 값으로 갈린다.** 없으면 스토리보드로 되돌린다
3. **영상 생성 MCP(Higgsfield 등) 자동 연동 확인** — 스킬 시작 시 가벼운 호출(잔액 조회 등)로 연결을 스스로 검증한다. 연결돼 있으면 사용자에게 다시 묻지 않고 그대로 사용하고, 미연결이면 커넥터 연결을 제안한다. 연결 자체가 불가하면 씬별 프롬프트만 정리해 주고 종료
4. **생성 전 비용 추정 고지 + 사용자 승인** (아래 비용 섹션) — 승인 없이 생성 호출 금지
5. **입력 소재 확보 — `content_type`별로 다르다**

   **(A) `content_type: sales` — A자료(제품 사진) 업로드가 필수 게이트**
   먼저 환경의 네트워크로 직접 업로드(presigned URL에 PUT)를 1회 시도한다. 성공하면 사용자 개입 없이 전 과정 자동. 실패(egress 차단, CONNECT 403 등)하면 재시도하지 말고 업로드 위젯(`media_upload_widget` 류)으로 전환해 드래그앤드롭으로 받는다 — 위젯은 사용자 브라우저가 직접 올리므로 환경 차단과 무관하다. 차단 환경이면 네트워크 허용 목록에 Higgsfield 전송 도메인(결과물·입력 CDN 및 `*.s3.amazonaws.com`) 추가를 1회 안내한다 — 추가되면 이후 다운로드·업로드 모두 자동화된다
   - **연결된 로컬 폴더가 있으면 먼저 스캔**한다: 제품 폴더에서 A자료 후보(제품컷·상세페이지 이미지)를 찾아 "이 파일을 위젯에 끌어다 놓으세요"라고 파일명·위치를 정확히 짚어 안내한다 — 사용자가 파일을 찾아 헤매지 않게 하는 것까지가 스킬의 책임
   - 업로드된 media_id를 확인한 뒤에만 생성을 시작한다. 위젯을 지원하지 않는 클라이언트면 higgsfield.ai 직접 업로드를 안내하고 `show_medias`로 도착을 확인한다
   - `sales_form`이 `affiliate`·`sponsored`면 **제품을 AI로 재생성하지 않는다** (실물과 달라지면 규정 위반 소지). 제품 컷은 공식 제공 소재·실촬영으로 돌리고 AI는 배경·상황 씬에만 쓴다. `resell`이면 사용자가 직접 촬영한 실물 사진만 A로 인정한다

   **(B) `content_type: habit` — A자료는 없는 것이 정상. 캐스팅 시트가 그 자리를 대신한다**
   팔 제품이 없으므로 제품 사진을 요구하지 않는다. **A자료가 없다는 이유로 이 스킬을 중단하지 않는다.**
   - **인물이 등장하는 기획이면** 스토리보드의 **캐스팅 시트**(person_group별 인물 수·성별·연령대·의상·분위기)가 필수 입력이다. 인물 씬이 있는데 캐스팅 시트가 없으면 스토리보드로 되돌린다. 인물이 없는 기획(손·기구 클로즈업, 다이어그램 위주)이면 캐스팅 시트 없이 진행한다
   - 선택 입력: B자료(인물·장소 톤 참고 이미지). 있으면 스틸 생성 프롬프트의 mood·lighting·wardrobe에만 반영하고 **소스 이미지로 쓰지 않는다**
   - 업로드가 필요한 자료가 없으면 업로드 절차 전체를 건너뛴다

## 생성 파이프라인 (씬 단위 반복)

```
[Step 0] 인물 일관성 결정 (인물 등장 시 필수, 아래 의사결정 트리)
   ↓
[Step 1] 씬 스틸 이미지 생성
   └─ (sales) 제품 등장 씬: 레퍼런스 A자료를 소스로 (형태 보존)
   └─ (habit) 동작 시연 씬: 캐스팅 시트 기반 text-to-image로 스틸 생성 (아래 [습관형 생성 경로])
   └─ 상황/배경 씬: B자료의 무드 묘사를 프롬프트로 (B를 소스로 쓰지 않음)
   └─ 인물 등장 씬: 스틸 생성 필수 — 이 스틸이 인물의 "정답지"가 된다 (아래 인물 일관성 규칙)
   └─ 캐릭터 씬: character_id 전달 (Step 0 사용 시)
   ↓
[Step 2] image-to-video 변환
   └─ Step 1 이미지를 start_image(첫 프레임) 소스로, 모션 프리셋 적용 (아래 표)
   └─ ⚠️ 인물 등장 씬은 이 경로가 유일한 허용 경로 — 참조 이미지만 넣은 text-to-video 직행 금지
      (참조는 제품 형태만 보존하고 인물은 매 생성마다 새로 발명되어, 클립 중간에 사람이 바뀌는
      identity switching이 발생한다. 실제 실패 사례에서 확인된 규칙)
   └─ 제품 단독 씬(인물 없음)은 A자료 참조 직행 허용 (형태 보존 목적이 참조로 충족됨)
   └─ 클립 길이: 씬 길이를 덮는 최소 클립 단위 (통상 5초)
   ↓
[Step 3] 클립 검수
   └─ 체크: 제품 형태 왜곡 / 로고 깨짐 / 손가락·글자 오류 / 씬 목적 부합
   └─ 인물 씬 추가 체크: 클립 중간 인물 교체(identity switching) / 씬 간 동일 인물 유지 여부
   └─ 실행 환경이 클립 파일을 직접 열 수 없으면 검수 항목을 사용자에게 명시적으로 제시하고 확인을 받는다
   └─ 불합격 시 재생성 1회 (프롬프트 수정 후) — 2회 실패면 해당 씬 실촬영 전환 제안
   └─ 판정 결과를 조립 지시서 `review`에 기록한다: pass(합격) / fail(2회 실패, 조립 금지) /
      manual(파일을 열 수 없어 사용자 확인으로 대체) — assemble이 이 값을 게이트로 쓴다
   ↓
[Step 4] 조립 지시서 산출 (아래 형식)
```

## 습관형(`content_type: habit`) 생성 경로

습관형은 팔 제품이 없고 **화면의 주인공이 사람의 동작**이다. 판매형 경로를 그대로 쓰면 "정지 장면에 줌만 걸린 클립"이 나오고 동작의 횟수·시간이 화면에 남지 않는다. 아래 규칙으로 분기한다.

**1. 인물 앵커 스틸 — 캐스팅 시트에서 만든다**
- 스토리보드 캐스팅 시트의 그룹 정의(인물 수·성별·연령대·의상·분위기)를 그대로 text-to-image 프롬프트로 옮겨 **그룹별 앵커 스틸 1장**을 먼저 만든다
- 이 앵커가 A자료 자리를 대신한다 — 이후 모든 `P1` 씬 스틸은 앵커를 인물 참조로 함께 전달해 "same person as the reference image, different pose/angle"로 생성한다 (인물 일관성 규칙 b와 동일)
- **앵커 스틸은 승인 게이트 대상이다** (규칙 c). 얼굴·체형·의상이 타깃과 어긋나면 여기서 다시 만드는 것이 클립 재생성보다 훨씬 싸다

**2. 동작 시연 — 스틸 1장으로 처리하지 않는다 (필수)**
동작 1개당 **최소 2장의 스틸**을 만들고 각각 짧은 클립으로 변환해 교차컷한다:

| 스틸 | 내용 | 클립 |
|---|---|---|
| 시작 자세 | 동작의 출발 프레임 (정면) | 1.5~2초, slow_zoom |
| 정점 자세 | 힘이 들어간 순간 (측면 — 관절 각도가 보이는 각도) | 1.5~2초, slow_zoom 또는 static |

- 두 스틸은 **같은 앵커·같은 의상·같은 배경**으로 생성한다. 앵커 참조를 빼면 두 컷의 사람이 달라진다
- 씬 시간표가 그 동작에 4초 이상을 배정했으면 [시작 → 정점 → 시작] 3컷으로 늘린다
- **한 씬이 클립 2~3개로 쪼개지므로 조립 지시서에 `cut` 번호로 싣는다** — 아래 [멀티컷 씬 표기] 규칙
- **횟수·시간은 화면 텍스트로 전달한다** — AI 클립은 반복 횟수를 정확히 그리지 못한다. 스토리보드 자막 컬럼에 `10회 × 3세트`, `15초 유지` 같은 카운트 자막이 없으면 스토리보드로 되돌려 넣는다. 조립 단계가 이 자막을 번인한다

**3. 실촬영 권고와 그 거부 시**
- 동작 시연 씬은 실촬영이 1순위다. 이 사실을 **생성 시작 전에 1회 고지**한다 (관절 각도·손발 개수 왜곡이 잦다)
- 사용자가 실촬영을 거부하면 위 2스틸 교차컷이 표준 경로다. 그래도 동작이 읽히지 않으면 마지막 폴백은 **정지 스틸 + 화살표·궤적 오버레이 + 카운트 자막**(다이어그램형)이다 — 부정확한 움직임을 보여주느니 정확한 그림을 보여준다
- 어떤 경로를 썼는지 조립 지시서 `clips[].note`에 남긴다

**4. 멀티컷 씬 표기 (한 씬 = 클립 2개 이상일 때 — 필수)**
- `clips[]`에 **같은 `scene` 값의 항목을 여러 개** 싣고, 각 항목에 `"cut": 1`, `"cut": 2` …를 붙인다 (단일 컷 씬은 `"cut": 1`)
- 씬의 배정 초를 컷 수만큼 나눠 `"cut_seconds"`에 적는다 — 합이 그 씬의 배정 초와 정확히 같아야 한다 (예: 4.0초 3컷 → 1.4 / 1.4 / 1.2)
- `assembly.sequence`는 씬 번호만 적고, 같은 씬 안의 순서는 `cut` 오름차순이 정본이다
- 파일명은 `scene{씬}-{컷}` 규칙으로 저장하도록 지시한다 (`scene4-1.mp4`, `scene4-2.mp4`) — 조립이 폴더 스캔으로 매칭한다
- 나레이션은 **그 씬의 첫 컷(`cut: 1`)에만** 싣는다. 나머지 컷의 `narration`·`narration_file`은 `null` (오디오는 씬 시작 시각 기준으로 한 번만 배치된다)

**5. 안전 주의 문구**
- 습관형은 안전 주의 자막이 필수다. 해당 자막이 걸린 씬의 스틸은 **글자가 얹힐 하단 여백을 비워** 생성한다 (인물이 화면 하단을 채우면 자막이 얼굴을 가린다)

## 모션 프리셋 (씬 역할 기준 자동 매핑)

`role` 값은 아래 표의 **영문 키로 고정**한다 — 조립 지시서 `clips[].role`에 이 값을 그대로 싣는다.

| 씬 역할 (`role`) | 프리셋 | 이유 |
|---|---|---|
| `hook` (0-3초) | impact_zoom (빠른 줌인) 또는 reveal | 첫 프레임에서 시선 고정 |
| `product_closeup` 제품 클로즈업 | orbit 또는 slow_zoom | 제품 형태를 안정적으로 보여줌 |
| `usage` 상황/사용 장면 | pan (좌우 이동) 또는 handheld | 생활감·현장감 |
| `demo` 동작 시연 (habit) | slow_zoom 또는 static | 관절 각도가 흔들리지 않게 |
| 인물 등장 씬 (위 역할과 겹칠 수 있음) | slow_zoom·pan·handheld 중 택1 (저위험 한정) | 카메라만 움직이고 장면 재구성 여지를 차단 |
| `evidence` 비교/증거 | static + 화면 분할 여지 | 정보 전달은 무빙 최소화 |
| `cta` | static 또는 slow_zoom_out | 자막·행동 지시가 주인공 |

사용자가 지정하면 그 값이 우선. 프리셋 이름은 연결된 MCP가 지원하는 실제 프리셋명으로 치환해 호출한다.

**인물 씬 모션 제한 (필수)**:
- 인물 씬 프롬프트에는 다음을 항상 명시한다: "one single continuous take, no camera cuts, no scene changes, the same person(s) with consistent clothing and appearance from first frame to last"
- 복잡한 행위(랠리·스매시·조리 등)를 영상 프롬프트로 연출하라고 요구하지 않는다 — 모델이 장면을 잘라 붙이며 인물이 바뀌는 주원인. 대신 **행위의 정점(임팩트 순간)을 Step 1 스틸에 고정**하고, 영상은 그 정지 장면에 카메라 무빙·미세 모션만 입힌다
- 임팩트가 필요한 씬은 5초 생성 후 정점 전후 2-3초만 트림해 쓰는 것을 기본으로 계획한다

## 인물 일관성 의사결정 트리 (Step 0, 인물 등장 시 필수)

시리즈물뿐 아니라 **단일 영상 안에서 같은 인물이 2개 이상 씬에 나오는 경우에도 반드시 발동**한다 (예: 씬 2 랠리와 씬 8 하이파이브에 같은 부부가 등장). 시청자는 한 편 안의 인물을 같은 사람으로 기대한다.

```
[Q1] 이 영상(또는 시리즈)에 사람/마스코트가 등장하나?
   ├─ 아니오 → Step 0 skip (제품 단독 모드)
   └─ 예 → [Q2]
[Q2] 같은 인물이 반복 등장하나? (시리즈 간 반복 OR 단일 영상 내 2개 이상 씬)
   ├─ 아니오 (씬마다 다른 단역) → 씬별 스틸 고정만으로 진행 (아래 인물 일관성 규칙 a만 적용)
   └─ 예 → [Q3]
[Q3] 캐릭터 등록 기능(Soul 등 character_id)을 현재 플랜에서 쓸 수 있나? (모델 폴백 규칙 참조)
   ├─ 예 → 등록된 id를 모든 인물 씬 생성에 전달 (없으면 등록 제안, 최초 1회 비용·시간 고지)
   └─ 아니오/불확실 → 앵커 스틸 방식으로 대체 (아래 인물 일관성 규칙 b)
```

- 실존 인물 얼굴로 캐릭터를 만들려면 본인 동의를 확인한다. 타인·유명인 얼굴은 거절

## 인물 일관성 규칙 (단일 영상 내)

- **a. 씬 내 일관성 — 스틸 고정**: 인물 등장 씬은 반드시 Step 1 스틸 → start_image i2v 체인으로 생성한다. 스틸 한 프레임에 인물·의상·구도가 고정되므로 클립 중간에 사람이 바뀔 여지가 없다
- **b. 씬 간 일관성 — 앵커 스틸 재사용**: **스토리보드의 `person_group` ID가 기준이다.** 같은 `person_group`을 가진 씬들은 **그 그룹의 첫 인물 씬 스틸을 앵커**로 삼는다. 이후 씬의 스틸을 생성할 때 앵커 스틸을 인물 참조로 함께 전달해 "same people as the reference image, different pose/angle"로 지시한다 (character_id가 있으면 그것이 우선). 그룹별로 앵커를 따로 관리한다 — `P1`의 앵커를 `P2` 씬에 쓰지 않는다
- **c. 스틸 승인 게이트**: 인물 앵커 스틸은 영상 변환 전에 사용자에게 보여주고 확인받는다 — 스틸 재생성은 클립 재생성보다 수 배 싸다. 스틸이 승인된 뒤에만 i2v 크레딧을 쓴다
- **d. 검수 연동**: Step 3에서 "클립 중간 인물 교체 없음 + **같은 `person_group` 씬 간 동일 인물 유지**"를 명시적 체크 항목으로 확인한다. shorts-auditor도 같은 ID를 기준으로 프레임을 대조한다

## 모델 폴백 규칙 (플랜·환경 제약 대응)

생성 호출이 다음 오류로 거부되면 사용자에게 상황을 알리고 아래 순서로 대응한다. 폴백으로 모델이 바뀌면 **비용을 재추정해 다시 승인**받는다.

| 오류 | 대응 |
|---|---|
| 플랜 제한 ("Requires plus plan" 등) | 같은 계열의 경량/하위 모델(예: 상위 모델 → mini 변형) → 그래도 막히면 reference 지원 타 벤더 모델 순으로 폴백. 폴백 모델이 더 저렴한 경우가 많으니 단가를 다시 preflight |
| 레이트 리밋 (429) | 60-90초 대기 후 실패분만 재제출. 즉시 연속 재시도 금지 |
| 프리셋 추천 개입 (제출 대신 프리셋 제안 반환) | 의도한 연출이면 수락, 아니면 declined_preset_id를 붙여 원래 요청 재제출 |
| 업로드 위젯 미지원 클라이언트 | higgsfield.ai 직접 업로드 안내 후 `show_medias`로 media_id 확인 (사전 조건 5-A) |
| 생성 실패 (과금 없음 확인) | 프롬프트를 단순화(행위·카메라 지시 축소)해 1회 재생성 |

- 캐릭터 등록(Soul 등)도 플랜 게이팅 대상일 수 있다 — 막히면 앵커 스틸 방식(인물 일관성 규칙 b)이 표준 대체 경로다

## 비용 추정 (생성 전 필수 고지)

```
📊 생성 비용 추정
- 씬 수: N개 (스틸 N장 + 클립 N개)
- (habit) 동작 시연 씬은 **씬당 스틸 2장·클립 2개**로 계산하고, 배정 4초 이상인 동작 씬은 **3컷(스틸 2장·클립 3개)**으로 계산한다 + 그룹별 앵커 스틸 1장 추가
- 재생성 예비: +20% 가정
- 예상 크레딧/비용: [연결된 MCP의 단가 기준으로 계산]
- 총액이 확실치 않으면 "이미지 1장+클립 1개 단가 × 씬 수 × 1.2" 범위로 제시
진행할까요? (일부 씬만 먼저 생성하는 것도 가능 — 훅 씬 1개 테스트 권장)
```

- 첫 실행이면 **훅 씬 1개만 테스트 생성 → 품질 확인 → 나머지 일괄**을 기본으로 제안한다 (전량 생성 후 스타일이 안 맞으면 비용 전액 손실)

## 출력 형식 (조립 지시서)

**이 지시서는 shorts-assemble의 입력 데이터다.** 사람이 읽는 편집 순서표가 아니라 다음 스킬이 파싱하는 계약이므로, 필드명을 임의로 바꾸거나 빼지 않는다. 필드명은 스토리보드 컬럼명과 일치시킨다.

```json
{
  "storyboard_ref": "제품명-v1",
  "content_type": "sales",
  "sales_form": "affiliate",
  "character_id": null,
  "scene_timing": [
    {"scene": 1, "assigned": 3.0, "measured": 2.9},
    {"scene": 2, "assigned": 4.5, "measured": null}
  ],
  "clips": [
    {"scene": 1, "cut": 1, "cut_seconds": 3.0,
     "role": "hook", "duration": 5, "trim_to": "0.0-3.0",
     "motion": "impact_zoom", "source": "A자료 hero.jpg", "url": "...",
     "person_group": null, "person_anchor": null,
     "narration": "이게 된다고?", "narration_file": null,
     "review": "pass", "note": null},
    {"scene": 2, "cut": 1, "cut_seconds": 4.5,
     "role": "usage", "duration": 5, "trim_to": "0.5-5.0",
     "motion": "handheld", "source": "still_p1_anchor.png", "url": "...",
     "person_group": "P1", "person_anchor": "still_p1_anchor.png",
     "narration": "둘이서도 충분해요", "narration_file": "narr02.mp3",
     "review": "pass", "note": null}
  ],
  "assembly": {
    "sequence": [1,2,3],
    "subtitles": "스토리보드 자막 컬럼 참조 (타이밍은 scene_timing의 씬 구간)",
    "narration": "clips[].narration_file 참조 (없으면 assemble이 TTS 생성 여부를 확인)",
    "bgm_cue": "스토리보드 오디오 컬럼 참조",
    "export": "9:16 1080×1920, 씬별 trim_to 구간만 사용"
  },
  "ai_disclosure": "유튜브 업로드 시 '변경·합성된 콘텐츠' 공개 설정 필요"
}
```

필드 계약 — **아래 표에 없는 필드를 새로 만들지 않는다.** 각 필드를 읽는 곳은 다음과 같다:

| 필드 | 생산 | 소비 |
|---|---|---|
| `storyboard_ref` | 이 스킬 (스토리보드 제목-버전) | assemble·auditor가 "어느 스토리보드와 대조할지" 식별 |
| `cut` / `cut_seconds` | 이 스킬 (단일 컷 씬은 `1` / 씬 배정 초) | assemble의 컷 순서·씬 구간 분할 |
| `duration` | 생성 클립의 원본 길이(초) | assemble이 `trim_to` 유효성 검사 |
| `motion` | 적용한 모션 프리셋명 | assemble 리포트 · 재생성 시 이 스킬 |
| `source` | 스틸·A자료 등 입력 소스 파일명 | auditor의 제품·인물 일관성 대조 |
| `url` | 생성 결과 원격 URL (만료 가능) | assemble의 클립 직접 다운로드 |
| `assembly.sequence` | 씬 번호 순서 | assemble 연결 순서 (같은 씬 안은 `cut` 오름차순) |
| `assembly.subtitles` / `narration` / `bgm_cue` / `export` | 소스 위치 포인터 | assemble의 자막·오디오·렌더 설정 |
| `ai_disclosure` | 고정 문구 | assemble 리포트 → publish-kit 체크리스트 |
| `content_type` | 스토리보드에서 그대로 전달 | assemble 자막 규칙 · publish-kit 고지 · auditor 판정 기준 |
| `sales_form` | 스토리보드에서 그대로 전달 (`habit`이면 `null`) | publish-kit 고지 표 · auditor 고지 검사 |
| `scene_timing` | 스토리보드 씬 시간표를 그대로 옮김 | **assemble의 길이 정합·자막 타이밍의 유일한 기준** |
| `character_id` | Step 0에서 캐릭터를 등록했으면 그 ID, 아니면 `null` | 이 스킬의 후속 씬 생성 · auditor의 인물 일관성 참고 |
| `role` | 모션 프리셋 표의 **영문 키** (`hook`/`product_closeup`/`usage`/`demo`/`evidence`/`cta`) | 이 스킬의 프리셋 매핑 · auditor의 씬 비중 판정 |
| `trim_to` | 생성 클립(5초)에서 씬 길이만큼 잘라 쓸 구간 | assemble Step 2 트림 |
| `person_group` | **스토리보드 씬 표의 값과 같은 ID.** 인물 없는 씬은 `null` | auditor 그룹별 프레임 대조 |
| `person_anchor` | 그 그룹에 실제로 쓴 앵커 스틸 파일명(또는 character_id). `person_group`이 있으면 반드시 채운다 | auditor가 앵커 스틸 ↔ 클립 프레임을 대조 |
| `narration` / `narration_file` | 스토리보드 나레이션 문장 / TTS 파일명(미생성이면 `null`) | assemble 오디오 믹스 |
| `review` | `pass` \| `fail` \| `manual` (Step 3 결과) | **assemble이 `pass`가 아닌 클립은 조립하지 않는다** — 사용자에게 보고하고 재생성·실촬영 선택을 받는다 |
| `note` | 특이 처리(습관형 2스틸 교차컷, 다이어그램 폴백 등). 없으면 `null` | assemble 리포트·auditor 참고 |

- 클립 URL은 만료될 수 있음을 지시서에 명기하고 즉시 다운로드를 권장한다

## 이 스킬을 사용하지 말아야 할 때

- **스크립트·콘티가 아직 없음** → shorts-script / shorts-storyboard 먼저
- **단일 이미지·단일 클립만 필요** → 영상 생성 MCP 직접 호출이 빠름
- **실촬영으로 확정된 프로젝트** → 본 스킬을 건너뛰고 스토리보드 → **shorts-assemble**로 간다 (촬영 체크리스트는 스토리보드 산출물에 있다)
- **상세페이지용 이미지 세트** → 본 플러그인 범위 밖 (상세페이지 이미지 전용 스킬 사용)
