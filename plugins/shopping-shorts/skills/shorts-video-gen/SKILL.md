# 쇼핑쇼츠 영상 생성 (Video Generation Orchestrator)

**책임 한 줄**: 확정된 스토리보드(씬 표 + 씬 시간표 + 샷 플랜) + (sales) 레퍼런스 A자료 / (habit) 캐스팅 시트 입력 → 샷 단위 연속 생성 체인 실행 → 원본 대조·연결부 검수된 클립 세트 + 조립 지시서 반환.

## 두 개의 1급 실패 — 아키텍처가 막는 것

1. **제품 왜곡**: 라벨 글자·로고·색·비율이 원본과 달라지는 것. 생성 모델은 제품을 재해석해 다시 그리므로, 제품 픽셀이 **생성을 통과하는 횟수를 최소화**하는 것만이 근본 대책이다. 제품 실사진(A)은 이미지 모델로 씬 스틸을 재생성하지 않고(금지 — 2단 통과로 왜곡 누적) 영상 모델의 참조 입력으로 **직접** 전달한다. 상세: **references/product-fidelity.md** (제품 등장 샷이 하나라도 있으면 작업 전 읽는다)
2. **슬라이드쇼**: 씬마다 독립 스틸에 카메라 무빙만 입혀 이어붙이면 "사진을 붙인 영상"이 된다. 연속성은 편집이 아니라 **생성 단계에서** 확보한다 — 씬 2-3개를 샷 하나로 묶어 연속 생성하고, 샷 사이는 이어가기(video_extension)/전환 생성(start+end frame)으로 잇는다. 상세: **references/shot-continuity.md** (생성 실행 전 반드시 읽는다)

예외는 목적이 있는 곳에만: 인물 앵커 스틸(identity switching 방지 — 실패 사례 기반)과 습관형 동작 2스틸 교차컷(자세 정확도)은 스틸 경로를 유지한다. 이 스틸들은 "생성된 인물"의 정답지라 제품 왜곡 문제가 없다.

## 사전 조건 (모두 충족해야 시작)

1. shorts-storyboard 산출물이 확정됨 (없으면 그 스킬로 먼저). **씬 표의 8개 고정 컬럼(#·시간·화면 구성·앵글/무빙·나레이션·자막·오디오·person_group)과 씬 시간표, 그리고 AI 생성 경로면 샷 플랜(샷 ID·씬 범위·연결 방식·공통 스타일 프리픽스)**이 있어야 한다
   - `person_group` 반려 조건은 **인물이 등장하는 씬이 있는데 그 씬의 ID가 비어 있을 때**다. 인물이 아예 없는 기획(전 씬 `—`)은 정상이며 제품 단독 모드로 진행한다
   - 샷 플랜이 없는 구버전 스토리보드면 shot-continuity.md의 그룹핑 규칙으로 샷 플랜을 만들어 사용자 확인 후 진행한다
2. **`content_type` 확인** (`sales` | `habit`) — 스토리보드 표 아래에 있다. **아래 사전 조건 5(5-A/5-B)와 생성 경로가 이 값으로 갈린다.** 없으면 스토리보드로 되돌린다
3. **영상 생성 MCP(Higgsfield 등) 자동 연동 확인** — 스킬 시작 시 가벼운 호출(잔액 조회 등)로 연결을 스스로 검증한다. 연결돼 있으면 사용자에게 다시 묻지 않고 그대로 사용하고, 미연결이면 커넥터 연결을 제안한다. 연결 자체가 불가하면 샷별 프롬프트 + 참조 매핑만 정리해 주고 종료
4. **비용 게이트 사다리 준수** (아래 섹션) — `get_cost` 실측 고지·승인 없이 생성 호출 금지, **드래프트(G2) 승인 전 본 생성 해상도(1080p) 호출 금지**
5. **입력 소재 확보 — `content_type`별로 다르다**

   **(A) `content_type: sales` — A자료(제품 사진) 업로드가 필수 게이트**
   먼저 환경의 네트워크로 직접 업로드(presigned URL에 PUT)를 1회 시도한다. 성공하면 사용자 개입 없이 전 과정 자동. 실패(egress 차단, CONNECT 403 등)하면 재시도하지 말고 업로드 위젯(`media_upload_widget` 류)으로 전환해 드래그앤드롭으로 받는다 — 위젯은 사용자 브라우저가 직접 올리므로 환경 차단과 무관하다. 차단 환경이면 네트워크 허용 목록에 Higgsfield 전송 도메인(결과물·입력 CDN 및 `*.s3.amazonaws.com`) 추가를 1회 안내한다
   - **연결된 로컬 폴더가 있으면 먼저 스캔**한다: 제품 폴더에서 A자료 후보를 찾아 파일명·위치를 정확히 짚어 안내한다. **다각도(정면·측면·상단)가 있으면 전부 반입한다** — 참조 각도가 많을수록 왜곡이 줄어든다 (권장 3~5장, reference-analysis.md의 A자료 표)
   - 업로드된 media_id를 확인한 뒤에만 생성을 시작한다. 위젯을 지원하지 않는 클라이언트면 higgsfield.ai 직접 업로드를 안내하고 `show_medias`로 도착을 확인한다
   - 제품 등장 샷이 있는데 A가 없으면 생성하지 않고 A를 요청한다 (프롬프트만으로 제품을 그리면 상상 제품이 나온다)
   - `sales_form`이 `affiliate`·`sponsored`면 **제품을 AI로 재생성하지 않는다** (실물과 달라지면 규정 위반 소지). 제품 컷은 공식 제공 소재·실촬영으로 돌리고 AI는 배경·상황 샷에만 쓴다. `resell`이면 사용자가 직접 촬영한 실물 사진만 A로 인정한다
   - **B자료가 영상이면**: 사용권이 확인된 자사·제조사 공식 영상에 한해 `video_references`(모션·무드 참조)로 반입할 수 있다. **타인 영상은 분석 전용 — 참조로 넘기지 않는다** (스토리보드의 출처별 사용 한계)

   **(B) `content_type: habit` — A자료는 없는 것이 정상. 캐스팅 시트가 그 자리를 대신한다**
   팔 제품이 없으므로 제품 사진을 요구하지 않는다. **A자료가 없다는 이유로 이 스킬을 중단하지 않는다.**
   - **인물이 등장하는 기획이면** 스토리보드의 **캐스팅 시트**(person_group별 인물 수·성별·연령대·의상·분위기)가 필수 입력이다. 인물 씬이 있는데 캐스팅 시트가 없으면 스토리보드로 되돌린다
   - 선택 입력: B자료(인물·장소 톤 참고 이미지). 있으면 스틸·샷 프롬프트의 mood·lighting·wardrobe에만 반영하고 **소스 이미지로 쓰지 않는다**
   - 업로드가 필요한 자료가 없으면 업로드 절차 전체를 건너뛴다

## 생성 파이프라인

```
[Step 0] 인물 일관성 결정 (인물 등장 시 필수, 아래 의사결정 트리)
   ↓
[Step 1] 샷 플랜 확정
   └─ 스토리보드의 샷 플랜 검토: 샷당 씬 2-3개(8-15초), 훅은 단독 샷,
      연결 방식(extension/cut/transition) 지정 확인 — 규칙은 shot-continuity.md
   └─ habit 동작 시연 씬은 샷으로 묶지 않는다 (2스틸 교차컷 경로 — 아래 습관형 섹션)
   ↓
[Step 2] 앵커 스틸 생성 (필요한 것만 — 제품 씬 스틸 재생성 금지)
   └─ 인물 앵커: person_group별 1장 (캐스팅 시트 기반, 인물 일관성 규칙 b)
      — 승인 게이트 대상 (규칙 c)
   └─ (habit) 동작 시연: 동작당 시작·정점 2스틸 (습관형 생성 경로)
   └─ 배경·인포그래픽 스틸: 제품·인물이 없는 삽화 컷에만 (선택)
   └─ (sales) 제품 등장 샷: 스틸을 만들지 않는다 — A media_id를 Step 3에서 직접 참조
   ↓
[Step 3] 샷 생성 (비용 게이트 G2 드래프트 → 승인 → G3 본 생성, 앵커 샷 → 체인 순서)
   └─ 앵커 샷(첫 샷): 참조 생성 — A 전체를 image_references로, 승인된 B 영상을
      video_references로, 프롬프트 = 공통 스타일 프리픽스 + 샷 비트
      (제품 형태를 텍스트로 재묘사하지 않는다)
   └─ 후속 샷 — 연결 방식별 (shot-continuity.md의 모드 트리):
      · extension → video_extension으로 직전 샷 job_id 이어가기 (같은 공간·연속 동작)
      · cut → 새 참조 생성 + 동일 A 참조 세트 + 동일 스타일 프리픽스 (공간 전환)
      · transition → start_image(직전 끝 프레임) + end_image(다음 첫 프레임)로 전환 생성
   └─ 인물 포함 샷: 해당 person_group 앵커 스틸을 start_image로 고정 + 연속 테이크
      문구 필수 — 참조만 넣은 text-to-video 직행 금지 (identity switching,
      실제 실패 사례 기반). extension 이어가기는 실제 픽셀을 연장하므로 허용
   └─ 공통: aspect_ratio "9:16" 명시, duration = 샷이 덮는 씬 배정 초 합계(모델
      허용 범위로 반올림), generate_audio 기본 false (오디오는 assemble의 3층 믹스)
   ↓
[Step 4] 검수 — 3종 대조
   └─ 원본 대조 (제품 등장 샷): A 원본 vs 제품 노출 프레임 (라벨·로고·색·비율·
      드리프트) — product-fidelity.md 체크리스트
   └─ 인물 검수: 클립 중간 인물 교체 없음 + 같은 person_group 씬 간 동일 인물 유지
   └─ 연결부(seam) 검사: 샷 경계의 끝/첫 프레임 연속성 — shot-continuity.md
   └─ 실행 환경이 클립 파일을 직접 열 수 없으면 검수 항목을 사용자에게 명시적으로
      제시하고 확인을 받는다
   └─ 불합격 시: 프롬프트 수정 반복이 아니라 **보존 대응 사다리 강등** (참조 강화 →
      정지 앵커 → 무생성 컷 → 실촬영, 불합격 샷에만 국소 적용) — product-fidelity.md
   └─ 판정 결과를 조립 지시서 `review`에 기록한다: pass / fail(2회 실패, 조립 금지) /
      manual(파일을 열 수 없어 사용자 확인으로 대체) — assemble이 이 값을 게이트로 쓴다
   ↓
[Step 5] 조립 지시서 산출 (아래 형식 — 샷 클립을 씬 단위로 분할 표기)
```

## 습관형(`content_type: habit`) 생성 경로

습관형은 팔 제품이 없고 **화면의 주인공이 사람의 동작**이다. 동작 시연 씬은 자세 정확도가 생동감보다 우선하므로 **스틸 교차컷 경로를 유지**하고, 나머지 씬(인트로·상황·CTA)은 샷 묶음 생성에 참여한다.

**1. 인물 앵커 스틸 — 캐스팅 시트에서 만든다**
- 스토리보드 캐스팅 시트의 그룹 정의(인물 수·성별·연령대·의상·분위기)를 그대로 text-to-image 프롬프트로 옮겨 **그룹별 앵커 스틸 1장**을 먼저 만든다
- 이 앵커가 A자료 자리를 대신한다 — 이후 모든 해당 그룹 씬·샷은 앵커를 start_image 또는 인물 참조로 함께 전달해 "same person as the reference image, different pose/angle"로 생성한다
- **앵커 스틸은 승인 게이트 대상이다** (규칙 c). 얼굴·체형·의상이 타깃과 어긋나면 여기서 다시 만드는 것이 클립 재생성보다 훨씬 싸다

**2. 동작 시연 — 스틸 1장으로 처리하지 않는다 (필수)**
동작 1개당 **최소 2장의 스틸**을 만들고 각각 짧은 클립으로 변환해 교차컷한다:

| 스틸 | 내용 | 클립 |
|---|---|---|
| 시작 자세 | 동작의 출발 프레임 (정면) | 1.5~2초, slow_zoom |
| 정점 자세 | 힘이 들어간 순간 (측면 — 관절 각도가 보이는 각도) | 1.5~2초, slow_zoom 또는 static |

- 두 스틸은 **같은 앵커·같은 의상·같은 배경**으로 생성한다. 앵커 참조를 빼면 두 컷의 사람이 달라진다
- 씬 시간표가 그 동작에 4초 이상을 배정했으면 [시작 → 정점 → 시작] 3컷으로 늘린다
- **한 씬이 클립 2~3개로 쪼개지므로 조립 지시서에 `cut` 번호로 싣는다** — 아래 [멀티컷 씬 표기] 규칙
- **횟수·시간은 화면 텍스트로 전달한다** — AI 클립은 반복 횟수를 정확히 그리지 못한다. 스토리보드 자막 컬럼에 `10회 × 3세트`, `15초 유지` 같은 카운트 자막이 없으면 스토리보드로 되돌려 넣는다. 조립 단계가 이 자막을 번인한다

**3. 실촬영 권고와 그 거부 시**
- 동작 시연 씬은 실촬영이 1순위다. 이 사실을 **생성 시작 전에 1회 고지**한다 (관절 각도·손발 개수 왜곡이 잦다)
- 사용자가 실촬영을 거부하면 위 2스틸 교차컷이 표준 경로다. 그래도 동작이 읽히지 않으면 마지막 폴백은 **정지 스틸 + 화살표·궤적 오버레이 + 카운트 자막**(다이어그램형)이다 — 부정확한 움직임을 보여주느니 정확한 그림을 보여준다
- 어떤 경로를 썼는지 조립 지시서 `clips[].note`에 남긴다

**4. 멀티컷 씬 표기 (한 씬 = 클립 2개 이상일 때 — 필수)**
- `clips[]`에 **같은 `scene` 값의 항목을 여러 개** 싣고, 각 항목에 `"cut": 1`, `"cut": 2` …를 붙인다 (단일 컷 씬은 `"cut": 1`)
- 씬의 배정 초를 컷 수만큼 나눠 `"cut_seconds"`에 적는다 — 합이 그 씬의 배정 초와 정확히 같아야 한다 (예: 4.0초 3컷 → 1.4 / 1.4 / 1.2)
- `assembly.sequence`는 씬 번호만 적고, 같은 씬 안의 순서는 `cut` 오름차순이 정본이다
- 파일명은 `scene{씬}-{컷}` 규칙으로 저장하도록 지시한다 (`scene4-1.mp4`, `scene4-2.mp4`) — 조립이 폴더 스캔으로 매칭한다
- 나레이션은 **그 씬의 첫 컷(`cut: 1`)에만** 싣는다. 나머지 컷의 `narration`·`narration_file`은 `null` (오디오는 씬 시작 시각 기준으로 한 번만 배치된다)

**5. 안전 주의 문구**
- 습관형은 안전 주의 자막이 필수다. 해당 자막이 걸린 씬의 스틸·샷은 **글자가 얹힐 하단 여백을 비워** 생성한다 (인물이 화면 하단을 채우면 자막이 얼굴을 가린다)

## 샷 카메라 연출 가이드 (프롬프트에 넣는 무빙 지시)

`role` 값은 아래 표의 **영문 키로 고정**한다 — 조립 지시서 `clips[].role`에 이 값을 그대로 싣는다.

| 씬 역할 (`role`) | 카메라 지시 | 이유 |
|---|---|---|
| `hook` (0-3초) | fast push-in / reveal | 첫 프레임에서 시선 고정. 제품 훅이면 줌 강도 중간 이하 |
| `product_closeup` 제품 클로즈업 | slow push-in / hold | **orbit(회전)·플립은 A에 해당 각도 사진이 있을 때만** — 없는 면을 상상 생성해 왜곡된다. A가 정면 1장뿐이면 push-in/hold로 제한 |
| `usage` 상황/사용 장면 | pan / handheld follow | 생활감. 샷 내 연속 동작으로 생동감 확보 (스틸+줌으로 흉내내지 않는다) |
| `demo` 동작 시연 (habit) | slow_zoom 또는 static | 관절 각도가 흔들리지 않게 (2스틸 교차컷 경로) |
| 인물 등장 샷 (위 역할과 겹칠 수 있음) | slow_zoom·pan·handheld 중 택1 (저위험 한정) | 카메라만 움직이고 장면 재구성 여지를 차단 |
| `evidence` 비교/증거 | hold + 화면 분할 여지 | 정보 전달은 무빙 최소화 |
| `cta` | hold / slow pull-back | 자막·행동 지시가 주인공 |

사용자가 지정하면 그 값이 우선 (단, A에 없는 각도의 orbit류 지정은 왜곡 위험을 고지하고 확인받는다).

**인물 샷 프롬프트 제한 (필수)**:
- 인물 샷 프롬프트에는 다음을 항상 명시한다: "one single continuous take, no camera cuts, no scene changes, the same person(s) with consistent clothing and appearance from first frame to last"
- 복잡한 행위(랠리·스매시·조리 등)를 한 프롬프트로 연출하라고 요구하지 않는다 — 모델이 장면을 잘라 붙이며 인물이 바뀌는 주원인. 행위의 정점을 앵커 스틸에 고정하고, 샷은 그 장면의 자연스러운 전후 동작·카메라 무빙까지만 지시한다
- 임팩트가 필요한 씬은 여유 있게 생성 후 정점 전후 구간만 trim_to로 쓰는 것을 기본으로 계획한다

## 인물 일관성 의사결정 트리 (Step 0, 인물 등장 시 필수)

시리즈물뿐 아니라 **단일 영상 안에서 같은 인물이 2개 이상 씬에 나오는 경우에도 반드시 발동**한다. 시청자는 한 편 안의 인물을 같은 사람으로 기대한다.

```
[Q1] 이 영상(또는 시리즈)에 사람/마스코트가 등장하나?
   ├─ 아니오 → Step 0 skip (제품 단독 모드)
   └─ 예 → [Q2]
[Q2] 같은 인물이 반복 등장하나? (시리즈 간 반복 OR 단일 영상 내 2개 이상 씬)
   ├─ 아니오 (씬마다 다른 단역) → 씬별 앵커 고정만으로 진행 (아래 규칙 a만 적용)
   └─ 예 → [Q3]
[Q3] 캐릭터 등록 기능(Soul 등 character_id)을 현재 플랜에서 쓸 수 있나? (모델 폴백 규칙 참조)
   ├─ 예 → 등록된 id를 모든 인물 샷 생성에 전달 (없으면 등록 제안, 최초 1회 비용·시간 고지)
   └─ 아니오/불확실 → 앵커 스틸 방식으로 대체 (아래 규칙 b)
```

- 실존 인물 얼굴로 캐릭터를 만들려면 본인 동의를 확인한다. 타인·유명인 얼굴은 거절

## 인물 일관성 규칙 (단일 영상 내)

- **a. 샷 내 일관성 — 앵커 고정**: 인물 등장 샷은 반드시 앵커 스틸 → start_image 체인으로 생성한다 (또는 직전 샷의 extension 이어가기 — 실제 픽셀을 연장하므로 인물이 유지된다). 참조 이미지만 넣은 text-to-video 직행은 금지 — 인물이 매 생성마다 새로 발명된다
- **b. 씬 간 일관성 — 앵커 스틸 재사용**: **스토리보드의 `person_group` ID가 기준이다.** 같은 `person_group`을 가진 씬·샷들은 **그 그룹의 앵커 스틸**을 공유한다. 새 샷을 생성할 때 앵커 스틸을 start_image 또는 인물 참조로 함께 전달해 "same people as the reference image, different pose/angle"로 지시한다 (character_id가 있으면 그것이 우선). 그룹별로 앵커를 따로 관리한다 — `P1`의 앵커를 `P2` 샷에 쓰지 않는다
- **c. 스틸 승인 게이트**: 인물 앵커 스틸은 영상 변환 전에 사용자에게 보여주고 확인받는다 — 스틸 재생성은 클립 재생성보다 수 배 싸다. 스틸이 승인된 뒤에만 i2v 크레딧을 쓴다
- **d. 검수 연동**: Step 4에서 "클립 중간 인물 교체 없음 + **같은 `person_group` 씬 간 동일 인물 유지**"를 명시적 체크 항목으로 확인한다. shorts-auditor도 같은 ID를 기준으로 프레임을 대조한다

## 모델 폴백 규칙 (플랜·환경 제약 대응)

기본 모델은 `models_explore`로 카탈로그를 조회해 **image_references·video_references·video_extension·start/end frame을 지원하는 Seedance 계열 최상위**를 선택한다 (product/identity 태그 우선, 사용자 지정 시 그 모델). 생성 호출이 다음 오류로 거부되면 사용자에게 상황을 알리고 아래 순서로 대응한다. 폴백으로 모델이 바뀌면 **비용을 재추정해 다시 승인**받는다.

| 오류 | 대응 |
|---|---|
| 플랜 제한 ("Requires plus plan" 등) | 같은 계열의 경량/하위 모델(예: 상위 모델 → mini 변형) → 그래도 막히면 동일 참조 롤을 지원하는 타 벤더 모델 순으로 폴백. 폴백 모델이 더 저렴한 경우가 많으니 단가를 다시 preflight |
| video_extension 미지원 모델로 폴백됨 | extension 연결을 "직전 샷 끝 프레임 캡처 → start_image" 방식으로 대체하고 seam 검사를 강화 |
| 레이트 리밋 (429) | 60-90초 대기 후 실패분만 재제출. 즉시 연속 재시도 금지 |
| 프리셋 추천 개입 (제출 대신 프리셋 제안 반환) | 의도한 연출이면 수락, 아니면 declined_preset_id를 붙여 원래 요청 재제출 |
| 업로드 위젯 미지원 클라이언트 | higgsfield.ai 직접 업로드 안내 후 `show_medias`로 media_id 확인 (사전 조건 5-A) |
| 생성 실패 (과금 없음 확인) | 프롬프트를 단순화(행위·카메라 지시 축소)해 1회 재생성 |

- 캐릭터 등록(Soul 등)도 플랜 게이팅 대상일 수 있다 — 막히면 앵커 스틸 방식(인물 일관성 규칙 b)이 표준 대체 경로다

## 비용 게이트 사다리 (승인 없이 생성 호출 금지)

영상 생성은 크레딧이 비싸다. 확신이 낮은 단계에서 비싼 호출을 하지 않도록, 게이트를 위에서부터 순서대로 통과한다:

| 게이트 | 비용 | 확인하는 것 |
|---|---|---|
| G0. 샷 플랜·프롬프트·(인물) 앵커 스틸 승인 | 0~스틸값 | 연출 방향, 샷 묶음, 인물 외형 (스틸 재생성은 클립보다 수 배 싸다) |
| G1. `get_cost:true` 실측 프리플라이트 | 0 | 드래프트·본 생성 각각의 실제 크레딧 (생성 없이 조회) — 합계 + 재생성 예비 +20% 고지 |
| G2. **드래프트 생성** — 앵커 샷 1개 | 저가 | 제품 재현·스타일·모션이 원하는 방향인지. 본 생성과 **동일한 프롬프트·참조**로, 해상도만 최저(480p)·fast/mini 변형 사용 |
| G3. 본 생성 (1080p, 전 샷 체인) | 고가 | G2에서 확정된 프롬프트·참조 그대로 실행 |

- **스틸 프리뷰를 비용 게이트로 쓰지 않는 이유**: 스틸을 승인해도 영상 모델이 프레임을 다시 그리므로 최종 결과를 예고하지 못하고(승인한 사진과 다른 영상이 나옴), 제품 씬에서는 스틸 재생성 자체가 왜곡원이다. 저해상도 **드래프트 영상**이 구도·모션·제품 재현을 모두 미리 보여주는 진짜 프리뷰다 (인물 앵커 스틸은 예외 — 인물 외형 확정용이지 영상 프리뷰가 아니다)
- 드래프트 불합격이면 프롬프트·참조를 수정해 **드래프트만** 재시도 — 본 생성 크레딧은 방향이 확정된 뒤에만 쓴다
- 무료 무제한 생성(unlim)을 지원하는 모델·잔여분이 있으면 드래프트에 우선 사용을 제안한다 (`models_explore`의 supports_unlim → `use_unlim`)
- 샷이 많으면(5개 이상) 드래프트는 앵커 + 성격이 다른 대표 샷 1개까지로 제한한다
- (habit) 비용 계산: 동작 시연 씬은 **씬당 스틸 2장·클립 2개**, 배정 4초 이상이면 **3컷**으로 계산 + 그룹별 앵커 스틸 1장 추가

## 출력 형식 (조립 지시서)

**이 지시서는 shorts-assemble의 입력 데이터다.** 필드명을 임의로 바꾸거나 빼지 않는다. **샷으로 연속 생성한 클립도 씬 단위로 분할해 싣는다** — 같은 샷에서 나온 인접 씬들은 **같은 `url`을 공유하고 `trim_to`로 각자 구간을 지정**한다 (연속 영상을 씬 경계에서 잘라 다시 붙이면 프레임이 동일해 이음새가 없다. assemble은 url 단위로 1회만 다운로드).

```json
{
  "storyboard_ref": "제품명-v1",
  "content_type": "sales",
  "sales_form": "affiliate",
  "character_id": null,
  "engine": "higgsfield/<실제 모델 id>",
  "references": {"product": ["media_id…"], "motion": [], "person_anchors": {"P1": "still_p1_anchor.png"}},
  "scene_timing": [
    {"scene": 1, "assigned": 3.0, "measured": 2.9},
    {"scene": 2, "assigned": 4.5, "measured": null}
  ],
  "shots": [
    {"shot": "S1", "scenes": [1, 2], "mode": "reference", "duration": 8, "url": "...",
     "seam_to_next": "extension", "seam_check": "pass"}
  ],
  "clips": [
    {"scene": 1, "cut": 1, "cut_seconds": 3.0, "shot": "S1",
     "role": "hook", "duration": 8, "trim_to": "0.0-3.0",
     "motion": "fast push-in", "source": "A자료 hero.jpg (direct reference)", "url": "...",
     "person_group": null, "person_anchor": null,
     "narration": "이게 된다고?", "narration_file": null,
     "review": "pass", "note": null},
    {"scene": 2, "cut": 1, "cut_seconds": 4.5, "shot": "S1",
     "role": "usage", "duration": 8, "trim_to": "3.0-7.5",
     "motion": "handheld follow", "source": "still_p1_anchor.png", "url": "...(S1과 동일)",
     "person_group": "P1", "person_anchor": "still_p1_anchor.png",
     "narration": "둘이서도 충분해요", "narration_file": "narr02.mp3",
     "review": "pass", "note": null}
  ],
  "assembly": {
    "sequence": [1,2,3],
    "subtitles": "스토리보드 자막 컬럼 참조 (타이밍은 scene_timing의 씬 구간)",

  },
  "ai_disclosure": "유튜브 업로드 시 '변경·합성된 콘텐츠' 공개 설정 필요"
}
```

필드 계약 — **아래 표에 없는 필드를 새로 만들지 않는다.** 각 필드를 읽는 곳은 다음과 같다:

| 필드 | 생산 | 소비 |
|---|---|---|
| `storyboard_ref` | 이 스킬 (스토리보드 제목-버전) | assemble·auditor가 "어느 스토리보드와 대조할지" 식별 |
| `engine` / `references` | 이 스킬 (사용 모델·반입 media_id) | auditor의 소스 추적 · 재생성 시 이 스킬 |
| `shots[]` | 이 스킬 (샷 ID·씬 범위·생성 모드·seam 검사 결과) | auditor의 연결부 대조 · 재생성 시 이 스킬 |
| `shot` (clips[]) | 그 클립이 나온 샷 ID (스틸 경로 클립은 `null`) | assemble의 url 중복 다운로드 방지 · 같은 shot 인접 씬 경계는 전환 효과 생략 |
| `cut` / `cut_seconds` | 이 스킬 (단일 컷 씬은 `1` / 씬 배정 초) | assemble의 컷 순서·씬 구간 분할 |
| `duration` | 생성 클립(샷)의 원본 길이(초) | assemble이 `trim_to` 유효성 검사 |
| `motion` | 적용한 카메라 연출 지시 | assemble 리포트 · 재생성 시 이 스킬 |
| `source` | A자료 직접 참조·앵커 스틸 등 입력 소스 | auditor의 제품·인물 일관성 대조 |
| `url` | 생성 결과 원격 URL (만료 가능) | assemble의 클립 직접 다운로드 (같은 url은 1회) |
| `assembly.sequence` | 씬 번호 순서 | assemble 연결 순서 (같은 씬 안은 `cut` 오름차순) |
| `assembly.subtitles` / `narration` / `bgm_cue` / `export` | 소스 위치 포인터 | assemble의 자막·오디오·렌더 설정 |
| `ai_disclosure` | 고정 문구 | assemble 리포트 → publish-kit 체크리스트 |
| `content_type` | 스토리보드에서 그대로 전달 | assemble 자막 규칙 · publish-kit 고지 · auditor 판정 기준 |
| `sales_form` | 스토리보드에서 그대로 전달 (`habit`이면 `null`) | publish-kit 고지 표 · auditor 고지 검사 |
| `scene_timing` | 스토리보드 씬 시간표를 그대로 옮김 | **assemble의 길이 정합·자막 타이밍의 유일한 기준** |
| `character_id` | Step 0에서 캐릭터를 등록했으면 그 ID, 아니면 `null` | 이 스킬의 후속 샷 생성 · auditor의 인물 일관성 참고 |
| `role` | 카메라 연출 가이드의 **영문 키** (`hook`/`product_closeup`/`usage`/`demo`/`evidence`/`cta`) | 이 스킬의 연출 매핑 · auditor의 씬 비중 판정 |
| `trim_to` | 샷 클립에서 그 씬이 쓰는 구간 | assemble Step 2 트림 |
| `person_group` | **스토리보드 씬 표의 값과 같은 ID.** 인물 없는 씬은 `null` | auditor 그룹별 프레임 대조 |
| `person_anchor` | 그 그룹에 실제로 쓴 앵커 스틸 파일명(또는 character_id). `person_group`이 있으면 반드시 채운다 | auditor가 앵커 스틸 ↔ 클립 프레임을 대조 |
| `narration` / `narration_file` | 스토리보드 나레이션 문장 / TTS 파일명(미생성이면 `null`) | assemble 오디오 믹스 |
| `review` | `pass` \| `fail` \| `manual` (Step 4 결과) | **assemble이 `pass`가 아닌 클립은 조립하지 않는다** — 사용자에게 보고하고 재생성·실촬영 선택을 받는다 |
| `note` | 특이 처리(습관형 2스틸 교차컷, 다이어그램 폴백, 보존 사다리 강등 등). 없으면 `null` | assemble 리포트·auditor 참고 |

- 클립 URL은 만료될 수 있음을 지시서에 명기하고 즉시 다운로드를 권장한다

## 이 스킬을 사용하지 말아야 할 때

- **스크립트·콘티가 아직 없음** → shorts-script / shorts-storyboard 먼저
- **단일 이미지·단일 클립만 필요** → 영상 생성 MCP 직접 호출이 빠름
- **실촬영으로 확정된 프로젝트** → 본 스킬을 건너뛰고 스토리보드 → **shorts-assemble**로 간다 (촬영 체크리스트는 스토리보드 산출물에 있다)
- **상세페이지용 이미지 세트** → 본 플러그인 범위 밖 (상세페이지 이미지 전용 스킬 사용)

## 다음 단계 (체이닝)

체인 위상: **shorts-script → shorts-storyboard → shorts-video-gen(AI 생성 시) → shorts-assemble → shorts-publish-kit**

클립 세트가 나오면 **자동 조립이 기본 경로**다: "클립을 연결 폴더에 넣어주시면 자막·전환·오디오까지 자동 조립해 완성 MP4를 만들어 드릴까요?" → **shorts-assemble**로 진행 (조립 지시서는 assemble의 입력 데이터가 된다 — 사용자에게 수동 편집을 요구하지 않는다). 완성본이 나오면 shorts-publish-kit으로 이어가며 AI 생성 사실을 전달한다 (합성 콘텐츠 공개 설정 체크리스트 반영).
