# 샷 연속성 (Shot Continuity) — 그룹핑 · 생성 모드 선택 · 연결부 검사

생성 실행 전 반드시 읽는다. "사진을 이어붙인 영상"(슬라이드쇼)을 막는 규칙이 전부 여기 있다.

## 왜 샷 단위인가

씬(2-5초)마다 독립된 스틸→클립을 만들면 씬 사이에 공유되는 것(공간·조명·제품 렌더·움직임)이 없어 슬라이드쇼가 된다. 연속성은 편집으로 못 만든다 — **생성 단계에서** 확보한다:

1. 씬 2-3개를 **샷 하나(8-15초)로 묶어 한 번에 연속 생성** — 샷 안의 움직임과 컷 전개는 모델이 만든다
2. 샷 사이는 **이어가기(video_extension)** 또는 **전환 생성(start/end frame)**으로 잇는다
3. 전 샷에 **동일한 참조 세트 + 공통 스타일 프리픽스**를 고정해 톤·제품 렌더 편차를 없앤다

조립 계약과의 관계: 샷은 생성 단위일 뿐, 조립 지시서에는 **씬 단위로 분할해 싣는다** (같은 url + 씬별 trim_to). 씬 시간표는 그대로 유효하다.

## 샷 그룹핑 규칙 (스토리보드에 샷 플랜이 없을 때 여기서 수행)

- **묶는다**: 같은 공간에서 이어지는 씬들, 하나의 동작 흐름(집어들기→사용→반응), 같은 인물(같은 person_group)이 연속 등장하는 씬들
- **분리한다**: 공간·시간대가 바뀌는 지점, 톤이 급전환되는 지점(문제 제기→해결), 인포그래픽/비교표 컷, **(habit) 동작 시연 씬**(2스틸 교차컷 경로 — 샷에 넣지 않는다)
- **훅(0-3초)은 단독 샷** — 가장 중요한 3초이므로 독립 생성·독립 재시도가 가능해야 한다
- 샷 길이 = 묶인 씬들의 배정 초 합계, 8-15초 기준 (모델 duration 상한 안에서). 30-45초 쇼츠면 통상 샷 3-5개
- 그룹핑 결과는 표(샷 ID·씬 범위·연결 방식)로 제시하고 사용자 확인 후 생성에 들어간다

## 생성 모드 선택 트리 (샷마다 — 스토리보드 전환 가이드의 extension/cut/transition 지정을 따른다)

```
[앵커 샷 = 첫 샷]
   → 참조 생성: A 전체 image_references (+ 사용권 확인된 B video_references)
     프롬프트 = 공통 스타일 프리픽스 + 샷 비트 서술
     인물 포함이면 앵커 스틸을 start_image로 (SKILL.md 인물 일관성 규칙 a)

[후속 샷 N]
   ├─ extension (같은 공간·연속 동작)
   │    → video_extension (forward): 직전 샷의 job_id를 참조로 넘겨 이어가기.
   │      제품 등장 샷이면 A image_references도 함께 유지.
   │      인물은 실제 픽셀이 연장되므로 identity가 유지된다 (연속 테이크 문구는 여전히 필수)
   ├─ cut (공간/상황 전환)
   │    → 새 참조 생성 (앵커와 동일한 A 참조 세트·person 앵커 + 동일 스타일 프리픽스)
   └─ transition (전환 자체가 연출 — 매치컷·모핑)
        → start_image(직전 샷 끝 프레임 캡처) + end_image(다음 샷 첫 프레임)로
          전환 구간을 별도 짧은 샷(2-4초)으로 생성
```

- 모드 이름(video_extension 등)은 `models_explore`로 조회한 **실제 모델의 파라미터·롤 이름으로 치환**해 호출한다. 미지원 모델이면 SKILL.md 모델 폴백 규칙(끝 프레임 캡처 → start_image 대체)
- extension 체인이 길어지면(3연장 이상) 화질·제품 드리프트가 누적된다 — 4샷 이상이면 중간에 참조 생성 샷을 한 번 끼워 리셋한다

## 호출 규약 (Higgsfield MCP)

```
1) 반입:  media_upload(files:[…]) → 반환된 upload_url로 파일 PUT
          → media_confirm → media_id 확보
          (직접 PUT 차단 환경이면 SKILL.md 사전 조건 5-A의 위젯 폴백)
2) 비용:  generate_video(params:{…, get_cost:true}) — 드래프트·본 생성 각각
          프리플라이트, 합산 고지 (비용 게이트 G1)
3) 드래프트: 본 생성과 동일한 prompt·medias로 앵커 샷 1개를 최저 해상도(480p)·
          fast/mini 변형으로 생성 → 사용자 승인 (비용 게이트 G2).
          승인 전에는 1080p 호출 금지
4) 생성:  generate_video(params:{
            model: "<카탈로그 실제 id>",
            prompt: "<공통 스타일 프리픽스 + 샷 비트 (+ 인물이면 연속 테이크 문구)>",
            aspect_ratio: "9:16",          ← 반드시 명시 (기본이 16:9인 모델 있음)
            duration: <샷이 덮는 씬 배정 초 합계>,
            generate_audio: false,          ← 오디오는 assemble의 3층 믹스 담당
            medias: [
              {value: "<A media_id>", role: "image_references"},  ← 제품 identity (전 샷 고정)
              {value: "<앵커 스틸 media_id>", role: "start_image"}, ← 인물 샷만
              {value: "<B media_id>", role: "video_references"},  ← 공식 영상만 (선택)
              {value: "<직전 job_id>", role: "<extension 롤>"}     ← 이어가기 샷만
            ]})
5) 대기:  job_status / jobs_wait → 완료 후 URL 수집 (만료 전 즉시 다운로드 권장)
```

- 여러 독립 샷(cut 연결)은 batch 도구로 병렬 생성 가능하되, **extension 체인은 순차** (직전 job_id가 필요하므로)

## 공통 스타일 프리픽스

앵커 샷 확정 시 한 줄로 뽑아 전 샷 프롬프트 맨 앞에 동일하게 붙인다:

```
예) "warm morning kitchen, soft window light, muted beige tones,
    handheld commercial look, vertical 9:16"
```

- 조명·색감·질감·촬영 룩 4요소만. 씬 내용은 넣지 않는다
- 스타일 프로필(C 레퍼런스)이 있으면 그 비주얼 톤에서, B 공식 영상이 있으면 그 무드에서 추출한다
- 스토리보드가 샷 플랜에 프리픽스를 확정해뒀으면 그 값을 그대로 쓴다

## 연결부(seam) 검사 — Step 4

샷 경계마다 직전 샷 **끝 프레임** vs 다음 샷 **첫 프레임**을 나란히 놓고 판정:

| 항목 | 합격 기준 |
|---|---|
| 공간·배경 | extension 연결이면 동일 공간으로 자연스럽게 이어짐. cut 연결이면 점프가 어색하지 않음 |
| 조명·색조 | 톤 점프 없음 (프리픽스 고정이 지켜졌는지) |
| 제품 상태 | 위치·방향·상태가 논리적으로 연속 (순간이동·복제 불합격) |
| 인물 | 같은 person_group이면 동일 인물·의상·머리 (identity switching 불합격) |

- 판정을 조립 지시서 `shots[].seam_check`에 기록한다 (pass / fail / manual)
- 불합격 시: 해당 연결만 재생성 — extension이면 프롬프트의 동작 서술을 더 구체화해 1회 재시도, 그래도 실패면 그 경계는 cut 연결로 설계 변경하고 사용자에게 고지
- 제품 재현 불합격은 여기가 아니라 product-fidelity.md의 보존 대응 사다리로, 인물 불합격은 SKILL.md 인물 일관성 규칙으로 처리

## 조립 지시서와의 연결

- 샷 클립을 씬 단위로 분할해 `clips[]`에 싣는다: 같은 샷의 씬들은 **같은 url**, 씬별 `trim_to` (샷 내 누적 시각 기준), `shot` 필드에 샷 ID
- `trim_to` 구간 합 = 샷이 덮는 씬들의 배정 초 합 = 샷 duration (허용 오차는 씬 시간표 기준 — 어긋나면 trim_to를 조정하고 assemble의 길이 정합 규칙에 맡긴다)
- 같은 shot의 인접 씬 경계는 이음새가 없으므로 **전환 효과를 넣지 않는다** — 자막·나레이션 싱크의 기준점일 뿐이다. 전환 효과는 샷과 샷 사이(cut/transition 경계)에만 지정한다
