# 쇼핑쇼츠 자동 조립 (Auto Assembly & Render)

**책임 한 줄**: 씬 클립 파일 + 나레이션 + 확정 스토리보드 입력 → 트림·연결·자막·오디오·전환을 코드로 합성 → 완성된 9:16 MP4 반환 (수동 편집 없음).

## 입력 확보

### 1. 클립 수집

1. **연결된 로컬 폴더 자동 스캔이 1순위** — 제품 폴더(또는 `clips/` 하위 폴더)에서 영상 파일을 찾아 씬 번호와 매칭한다. 파일명에 씬 번호가 있으면 자동 매칭(`scene2*.mp4`, `씬2*.mp4`), 없으면 생성 시각·길이로 추정하고 매칭표를 사용자에게 확인받는다
2. 생성 클립이 원격 URL로만 존재하면: **직접 다운로드를 먼저 시도한다** (네트워크 허용 목록에 Higgsfield CDN이 있으면 성공 — 사용자 개입 0). 차단으로 실패하면 재시도하지 말고 "클립을 연결 폴더에 넣어달라"고 파일 단위로 안내하고(Higgsfield 갤러리 → 다운로드 → 폴더 드래그 1회), 허용 목록에 CDN 도메인 추가를 1회 안내한다. 폴더에 들어온 뒤부터는 전 과정 자동
3. **실촬영 씬 클립도 같은 폴더에서 받는다** — 실촬영 프로젝트는 shorts-video-gen을 거치지 않고 shorts-storyboard에서 바로 이 스킬로 온다. 조립 지시서가 없으므로 스토리보드 씬 표를 직접 입력으로 쓴다
4. 일부 씬이 미확보면: 확보된 씬만으로 가조립본을 만들지, 기다릴지 사용자에게 묻는다

### 2. 나레이션 수집 (클립과 동등한 필수 입력)

**나레이션은 BGM의 부속물이 아니라 씬별로 매칭되는 1급 입력이다.** 아래 순서로 확보한다.

1. **연결 폴더에서 나레이션 오디오를 스캔한다** — `narr*.mp3`, `나레이션*.mp3`, `scene*_narr.*`, `씬*_나레이션.*`, `.wav`/`.m4a` 포함. 파일명에 씬 번호가 있으면 자동 매칭, 없으면 생성 시각 순 + 스토리보드 나레이션 컬럼의 순서로 대응시키고 **매칭표를 사용자에게 확인받는다**
2. 조립 지시서(shorts-video-gen 산출)가 있으면 `clips[].narration_file`을 우선 신뢰한다
3. **나레이션 파일이 없고 스토리보드 나레이션 컬럼은 채워져 있으면**: TTS 생성을 제안한다 — 영상 생성 MCP의 음성 생성 기능(Higgsfield `generate_audio` 등)으로 씬별 나레이션을 만든다. **크레딧 소모를 사전 고지하고 승인받는다.** 승인 없이 생성하지 않는다
4. 나레이션이 아예 없는 기획(자막만 있는 무음 나레이션 쇼츠)이면 그대로 진행하고, 리포트에 "나레이션 없음(의도된 구성)"으로 명시한다
5. 씬 표의 나레이션 컬럼이 통째로 비어 있으면 → 스토리보드가 불완전한 것이다. 임의로 채우지 말고 shorts-storyboard로 되돌린다

### 3. 타이밍 정보

스토리보드·조립 지시서에서 씬별 `trim_to`(사용 구간)·나레이션·자막·전환·오디오 큐를 읽는다. 조립 지시서가 없으면 스토리보드에서 직접 구성한다.

## 길이 정합 규칙 (나레이션 우선)

씬 시간은 shorts-script가 나레이션 실측 기준으로 확정한 값이다. 조립 단계는 그 값을 **검증하는 자리이지 재설계하는 자리가 아니다.** 나레이션 실측 길이와 배정된 씬 길이가 어긋나면 아래 순서로 처리한다:

| 차이 | 처리 |
|---|---|
| ±5% 이내 | `atempo`로 미세 보정 (0.95~1.05). 자연스러움 손상 없음 |
| 5~15% | **클립 쪽을 먼저 조정한다** — `trim_to` 구간을 늘리거나 줄여 씬 길이를 나레이션에 맞춘다. 총 길이 변화를 사용자에게 고지 |
| 15% 초과 | **자동 처리하지 않는다.** 스크립트 단계의 문장 길이 문제이므로 상황을 보고하고 ① 나레이션 문장 축약(shorts-script로 회귀) ② 해당 씬 클립 연장 재생성 중 선택을 받는다 |

- `atempo`를 0.9 미만·1.1 초과로 쓰지 않는다 — 그 구간부터 목소리가 눈에 띄게 부자연스러워진다
- 어떤 보정을 했든 **조정 사실과 수치를 조립 리포트에 명시한다**

## 조립 파이프라인 (ffmpeg 기본 경로)

```
[1] 정규화: 모든 클립을 1080×1920 / 30fps / H.264 / 48kHz로 통일
    ffmpeg -i in.mp4 -vf "scale=1080:1920:force_original_aspect_ratio=increase,crop=1080:1920,fps=30" \
      -c:v libx264 -preset medium -crf 18 -c:a aac -ar 48000 norm_sceneN.mp4
[2] 트림: 씬별 trim_to 구간만 추출 (-ss/-t, 재인코딩 방식으로 프레임 정확도 확보)
[3] 연결: concat demuxer로 씬 순서대로 연결. 전환이 지정된 경계는 xfade(0.2-0.3초)로 대체
    (와이프=wipeleft 등, 화이트 플래시=fade+white, 지정 없으면 하드컷)
[4] 오디오 믹스 (아래 3층 순서를 지킨다)
    ① 나레이션: 씬별 나레이션 파일을 해당 씬 시작 시각에 배치 (adelay). 기준 레벨 0dB
       - ffprobe로 각 나레이션 실측 길이를 먼저 확인하고 위 길이 정합 규칙을 적용
       - 씬 경계에서 나레이션이 잘리지 않게 앞뒤 0.1초 패딩 확인
    ② 클립 자체 오디오: 스토리보드 오디오 컬럼 기준으로 씬별 유지/음소거.
       유지하는 구간도 나레이션과 겹치면 -8dB 덕킹
    ③ BGM: 받았으면 -18dB 내외로 전 구간에 깔고, 나레이션 구간은 사이드체인 또는 -6dB 추가 덕킹
       BGM이 없으면 나레이션+클립 오디오만으로 완성하고
       "발행 전 유튜브 오디오 라이브러리에서 추가 가능"을 안내
    → 최종 믹스는 -14 LUFS 내외를 목표로 하고, 피크가 -1dBTP를 넘지 않게 리미팅
[5] 자막: ASS 자막 파일을 생성해 번인 (-vf "ass=subs.ass")
    - 타이밍: 스토리보드 자막 컬럼의 구간 그대로 (나레이션 컬럼이 아니라 자막 컬럼을 쓴다 — 둘은 다르다)
    - 위치: 세로 중앙~중하단, 하단 300px·우측 120px·상단 150px 침범 금지 (youtube-shorts-specs.md 안전영역)
    - 스타일: 굵은 고딕(Noto Sans KR 계열 설치 확인, 없으면 apt/fc 설치), 흰 글자 + 검정 외곽선 3px, 키워드만 옐로 강조 가능
    - 폰트 미존재 채로 렌더 금지 — 한글 깨짐(□□) 검수 실패의 최다 원인
    - (content_type: habit) 안전 주의 문구 자막이 스토리보드에 있으면 반드시 포함한다 — 누락 시 검수 FAIL 항목
[6] 최종 렌더: 1080×1920, H.264, 30fps, yuv420p, AAC. 총 길이가 스토리보드 총 길이 ±0.5초인지 확인
```

- 모든 중간 산출물은 작업 폴더에, 최종본만 전달한다

## Remotion 경로 (선택 — 모션 그래픽 자막)

정적 ASS 자막으로 부족한 경우(단어 단위 팝업, 카운트다운, 애니메이션 강조)에만 제안한다:
- Node + 헤드리스 크로미움이 있는 환경에서 `npm install remotion @remotion/cli @remotion/renderer`
- 씬 클립을 `<OffthreadVideo>`로 배치하고 자막을 React 컴포넌트로 렌더, `npx remotion render` (크로미움 경로가 고정된 환경이면 executablePath 지정)
- 렌더 시간이 ffmpeg 대비 수 배 길고 의존성 설치가 필요하므로 기본값이 아니다 — 사용자가 모션 자막을 원할 때만

## 검수 (렌더 후 필수)

1. 렌더된 MP4에서 프레임을 3-4장 추출해 직접 확인: 자막 안전영역 준수 / 한글 깨짐 없음 / 씬 순서 정확
2. 총 길이·해상도·fps를 ffprobe로 확인해 스토리보드와 대조
3. **오디오 확인**: 나레이션이 모든 해당 씬에 실제로 들어갔는지 파형·구간으로 확인한다 (무음 구간이 나레이션 씬과 겹치면 매칭 실패)
4. 이상 없으면 최종본을 사용자에게 전달하고 연결 폴더에 저장한다 (파일명: `{제품명 또는 주제}_shorts_final.mp4`)

## 출력

- 완성 MP4 1개 (+ 요청 시 자막 없는 클린본)
- 조립 리포트 4줄: 사용한 씬·트림 구간 / 나레이션 매칭·길이 보정 내역 / 자막·BGM 처리 / 총 길이·규격
- ⚠️ AI 생성 클립이 포함된 영상임을 리포트에 명시 — 유튜브 업로드 시 "변경·합성된 콘텐츠" 공개 설정 체크 (publish-kit에 전달)
- `content_type`을 리포트에 함께 실어 publish-kit으로 넘긴다 (제휴 고지 필요 여부가 여기서 갈린다)

## 이 스킬을 사용하지 말아야 할 때

- 클립이 하나도 없음 → shorts-video-gen(생성) 또는 실촬영 먼저
- 스토리보드 없이 "영상 파일만 이어붙여줘" → 가능하나 자막·타이밍 근거가 없음을 고지하고 단순 연결만 수행
- 남의 영상(타인 저작물)을 소재로 넣어달라는 요청 → 거절하고 분석 전용 원칙 안내 (shorts-storyboard의 참고 영상 분석 절차)

## 다음 단계 (체이닝)

체인 위상: **shorts-script → shorts-storyboard → shorts-video-gen(AI 생성 시) → shorts-assemble → shorts-publish-kit**

완성본이 나오면: "발행용 제목·설명·해시태그 세트를 만들까요?" → **shorts-publish-kit**으로 진행 (`content_type`·AI 생성 사실을 함께 전달). 발행 직전 **shorts-auditor** 검수를 제안하는 것이 표준 흐름이다.
