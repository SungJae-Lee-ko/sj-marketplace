# 쇼핑쇼츠 자동 조립 (Auto Assembly & Render)

**책임 한 줄**: 씬 클립 파일 + 확정 스토리보드 입력 → 트림·연결·자막·오디오·전환을 코드로 합성 → 완성된 9:16 MP4 반환 (수동 편집 없음).

## 입력 확보 (클립 수집)

1. **연결된 로컬 폴더 자동 스캔이 1순위** — 제품 폴더(또는 `clips/` 하위 폴더)에서 영상 파일을 찾아 씬 번호와 매칭한다. 파일명에 씬 번호가 있으면 자동 매칭(`scene2*.mp4`, `씬2*.mp4`), 없으면 생성 시각·길이로 추정하고 매칭표를 사용자에게 확인받는다
2. 생성 클립이 원격 URL로만 존재하면: **직접 다운로드를 먼저 시도한다** (네트워크 허용 목록에 Higgsfield CDN이 있으면 성공 — 사용자 개입 0). 차단으로 실패하면 재시도하지 말고 "클립을 연결 폴더에 넣어달라"고 파일 단위로 안내하고(Higgsfield 갤러리 → 다운로드 → 폴더 드래그 1회), 허용 목록에 CDN 도메인 추가를 1회 안내한다. 폴더에 들어온 뒤부터는 전 과정 자동
3. 실촬영 씬 클립도 같은 폴더에서 받는다. 일부 씬이 미확보면: 확보된 씬만으로 가조립본을 만들지, 기다릴지 사용자에게 묻는다
4. 스토리보드·조립 지시서에서 씬별 `trim_to`(사용 구간)·자막·나레이션·전환·오디오 큐를 읽는다. 조립 지시서가 없으면 스토리보드에서 직접 구성한다

## 조립 파이프라인 (ffmpeg 기본 경로)

```
[1] 정규화: 모든 클립을 1080×1920 / 30fps / H.264 / 48kHz로 통일
    ffmpeg -i in.mp4 -vf "scale=1080:1920:force_original_aspect_ratio=increase,crop=1080:1920,fps=30" \
      -c:v libx264 -preset medium -crf 18 -c:a aac -ar 48000 norm_sceneN.mp4
[2] 트림: 씬별 trim_to 구간만 추출 (-ss/-t, 재인코딩 방식으로 프레임 정확도 확보)
[3] 연결: concat demuxer로 씬 순서대로 연결. 전환이 지정된 경계는 xfade(0.2-0.3초)로 대체
    (와이프=wipeleft 등, 화이트 플래시=fade+white, 지정 없으면 하드컷)
[4] 자막: ASS 자막 파일을 생성해 번인 (-vf "ass=subs.ass")
    - 타이밍: 스토리보드 자막 컬럼의 구간 그대로
    - 위치: 세로 중앙~중하단, 하단 300px·우측 120px·상단 150px 침범 금지 (youtube-shorts-specs.md 안전영역)
    - 스타일: 굵은 고딕(Noto Sans KR 계열 설치 확인, 없으면 apt/fc 설치), 흰 글자 + 검정 외곽선 3px, 키워드만 옐로 강조 가능
    - 폰트 미존재 채로 렌더 금지 — 한글 깨짐(□□) 검수 실패의 최다 원인
[5] 오디오: 클립 자체 오디오는 스토리보드 오디오 컬럼 기준으로 씬별 유지/음소거.
    BGM 파일을 받았으면 -18dB 내외로 깔고 나레이션·효과음 구간은 사이드체인 또는 -6dB 추가 덕킹.
    BGM이 없으면 클립 오디오만으로 완성하고 "발행 전 유튜브 오디오 라이브러리에서 추가 가능"을 안내
[6] 최종 렌더: 1080×1920, H.264, 30fps, yuv420p, AAC. 총 길이가 스토리보드 총 길이 ±0.5초인지 확인
```

- 나레이션 TTS가 필요하면: 영상 생성 MCP의 음성 생성 기능(Higgsfield `generate_audio` 등)으로 씬별 나레이션을 만들어 [5]에서 믹스할 수 있다 — 크레딧 소모를 사전 고지하고 승인받는다
- 모든 중간 산출물은 작업 폴더에, 최종본만 전달한다

## Remotion 경로 (선택 — 모션 그래픽 자막)

정적 ASS 자막으로 부족한 경우(단어 단위 팝업, 카운트다운, 애니메이션 강조)에만 제안한다:
- Node + 헤드리스 크로미움이 있는 환경에서 `npm install remotion @remotion/cli @remotion/renderer`
- 씬 클립을 `<OffthreadVideo>`로 배치하고 자막을 React 컴포넌트로 렌더, `npx remotion render` (크로미움 경로가 고정된 환경이면 executablePath 지정)
- 렌더 시간이 ffmpeg 대비 수 배 길고 의존성 설치가 필요하므로 기본값이 아니다 — 사용자가 모션 자막을 원할 때만

## 검수 (렌더 후 필수)

1. 렌더된 MP4에서 프레임을 3-4장 추출해 직접 확인: 자막 안전영역 준수 / 한글 깨짐 없음 / 씬 순서 정확
2. 총 길이·해상도·fps를 ffprobe로 확인해 스토리보드와 대조
3. 이상 없으면 최종본을 사용자에게 전달하고 연결 폴더에 저장한다 (파일명: `{제품명}_shorts_final.mp4`)

## 출력

- 완성 MP4 1개 (+ 요청 시 자막 없는 클린본)
- 조립 리포트 3줄: 사용한 씬·트림 구간 / 자막·오디오 처리 / 총 길이·규격
- ⚠️ AI 생성 클립이 포함된 영상임을 리포트에 명시 — 유튜브 업로드 시 "변경·합성된 콘텐츠" 공개 설정 체크 (publish-kit에 전달)

## 이 스킬을 사용하지 말아야 할 때

- 클립이 하나도 없음 → shorts-video-gen(생성) 또는 실촬영 먼저
- 스토리보드 없이 "영상 파일만 이어붙여줘" → 가능하나 자막·타이밍 근거가 없음을 고지하고 단순 연결만 수행
- 남의 영상(타인 저작물)을 소재로 넣어달라는 요청 → 거절하고 분석 전용 원칙 안내 (shorts-storyboard의 참고 영상 분석 절차)
